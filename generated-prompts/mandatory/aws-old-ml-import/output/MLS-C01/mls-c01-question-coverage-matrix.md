# MLS-C01 Question Coverage Matrix

This matrix follows the current [AWS Certified Machine Learning - Specialty (MLS-C01) exam guide](https://docs.aws.amazon.com/aws-certification/latest/machine-learning-specialty-01.html). Domain weights describe scored-exam emphasis; they are not a required count for this 269-question local set. Current coverage estimates are based on a thematic review of the JSON files and are non-exclusive because one question can support multiple tasks.

| Domain / task | Exam weight | What should be covered | Current question coverage |
| --- | ---: | --- | --- |
| **1. Data Engineering** | **20%** | ML data repositories, ingestion, orchestration, scheduling, ETL, and distributed transformation | **~50 questions.** Storage and transformation are represented; streaming orchestration and production data pipelines need more depth. |
| 1.1 Create data repositories for ML | — | Data sources and storage choices across S3, databases, EFS, and EBS | **~22 questions.** S3, databases, and ML storage choices are covered; EFS/EBS-specific selection is limited. |
| 1.2 Identify and implement data ingestion | — | Batch vs. streaming, Kinesis, Data Firehose, EMR, Glue, Flink, and scheduling | **~14 questions.** Batch/streaming and AWS ingestion services appear, but orchestration and scheduling are thin. |
| 1.3 Identify and implement data transformation | — | ETL with Glue/EMR/Batch and MapReduce with Hadoop, Spark, and Hive | **~22 questions.** ETL and transformation concepts are present; distributed-framework trade-offs need expansion. |
| **2. Exploratory Data Analysis** | **24%** | Data sanitization, feature engineering, visualization, descriptive statistics, and cluster analysis | **~55 questions.** Missing-data handling, encoding, metrics, and preparation are strong; visualization and statistical interpretation need more coverage. |
| 2.1 Sanitize and prepare data for modeling | — | Missing/corrupt data, stop words, formatting, normalization, scaling, augmentation, labels, and labeling tools | **~24 questions.** Missing data, one-hot encoding, and training/test preparation are represented; labeling workflows are sparse. |
| 2.2 Perform feature engineering | — | Text/image/speech features, binning, tokenization, outliers, synthetic features, one-hot encoding, and dimensionality reduction | **~24 questions.** Encoding, tokenization, and preparation appear; outliers and dimensionality reduction need stronger coverage. |
| 2.3 Analyze and visualize data for ML | — | Graphs, time series, histograms, box plots, correlation, summary statistics, p-values, and elbow/cluster analysis | **~12 questions.** Clustering and evaluation concepts appear; graph interpretation and descriptive statistics are under-covered. |
| **3. Modeling** | **36%** | Problem framing, algorithm selection, training, optimization, and evaluation | **~175 questions.** This is the strongest domain, with broad algorithm and metric coverage; scenario depth varies by collection. |
| 3.1 Frame business problems as ML problems | — | When to use ML, supervised vs. unsupervised learning, classification, regression, forecasting, clustering, recommendation, and foundation models | **~35 questions.** Problem types and learning paradigms are well represented. |
| 3.2 Select appropriate models | — | XGBoost, logistic/linear regression, k-means, trees, random forests, RNNs, CNNs, ensembles, transfer learning, and LLMs | **~60 questions.** Algorithm characteristics and selection are extensively covered, though many are recall-oriented. |
| 3.3 Train ML models | — | Train/validation splits, cross-validation, gradient descent, loss/convergence, CPU/GPU, distributed training, Spark, and retraining | **~70 questions.** Training concepts and compute choices are strong; retraining and distributed scenarios need more depth. |
| 3.4 Perform hyperparameter optimization | — | Regularization, dropout, L1/L2, cross-validation, initialization, layers/nodes, learning rate, and tree parameters | **~32 questions.** Neural-network and regularization fundamentals appear; systematic tuning workflows are less represented. |
| 3.5 Evaluate ML models | — | Bias/variance, overfit/underfit, AUC/ROC, accuracy, precision, recall, RMSE, F1, confusion matrices, A/B tests, and model comparison | **~60 questions.** Metrics and evaluation are a major strength; online evaluation and engineering-cost trade-offs need more scenarios. |
| **4. ML Implementation and Operations** | **20%** | Performance, availability, service selection, security, deployment, monitoring, troubleshooting, and operationalization | **~85 questions.** SageMaker and AWS operations are covered; production reliability and endpoint operations need more applied questions. |
| 4.1 Build performant, available, scalable, resilient, fault-tolerant ML solutions | — | Logging/monitoring, multi-AZ/Region, AMIs, containers, Auto Scaling, rightsizing, load balancing, and best practices | **~30 questions.** Infrastructure and monitoring concepts appear; multi-Region resilience and capacity planning are limited. |
| 4.2 Recommend appropriate ML services and features | — | SageMaker built-ins vs. custom models, AWS ML application services, quotas, instance types, cost, and Spot training | **~45 questions.** SageMaker algorithms, compute, and AWS ML services are strong; quotas and Spot trade-offs need more depth. |
| 4.3 Apply AWS security practices to ML solutions | — | IAM, S3 policies, security groups, VPCs, encryption, anonymization, and secure data access | **~20 questions.** IAM, S3, VPC, and encryption are present; ML-specific anonymization scenarios are sparse. |
| 4.4 Deploy and operationalize ML solutions | — | Endpoints, inference, A/B tests, retraining pipelines, debugging, performance drops, and model monitoring | **~38 questions.** Deployment and inference are represented; monitoring drift, troubleshooting, and retraining need more applied coverage. |

The main MLS-C01 gaps are streaming data orchestration, visualization/statistical interpretation, distributed training trade-offs, systematic tuning, and production monitoring/retraining scenarios. Modeling coverage is broad but should continue shifting from recall toward multi-constraint applied problems.
